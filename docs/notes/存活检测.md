# 渗透测试 · 子域名探查完整流程

::: tip 说明
子域名探查是信息收集里回报率最高的一步。本篇把完整链路串起来：**证书透明日志 → DNS 解析 → 存活检测 → 指纹识别**，每一步讲清「为什么做、用什么工具、怎么做」。
:::

## 一、为什么子域名探查这么重要

一个公司的主站通常防护最严，反而是那些**子域名**（旧测试站、后台、没人管的系统）常年不更新、漏洞一抓一把。

**打个比方：** 你要进一栋大楼，正门有保安，但侧门、地下车库门、后门可能常年没锁。子域名探查就是把这些「侧门」全找出来。

完整链路四步：

```
① 证书透明日志 → ② DNS 解析 → ③ 存活检测 → ④ 指纹识别
   广撒网拿全       过滤解析不出的    筛掉僵尸域名     锁定技术栈
```

---

## 二、第一步：证书透明日志（广撒网，拿到尽可能全的域名）

### 为什么查证书「更全面」

证书透明日志（CT Log）的数据来源是**真实签发记录**：

- 只要一个子域名**签过 HTTPS 证书**，不管现在上不上线、DNS 还在不在，**记录都在**。
- 而字典爆破只能猜「字典里有的词」，证书日志是**客观事实**，不靠猜。

所以证书查出来的子域名，往往比爆破**多、准、还快**。

### 怎么做

```bash
# crt.sh 证书透明日志（纯公开数据，零安装）
curl -s "https://crt.sh/?q=%25.example.com&output=json" | jq -r '.[].name_value' | sort -u

# subfinder 聚合多源被动枚举（覆盖更广）
subfinder -d example.com -o subs.txt

# amass 被动枚举（聚合更多数据源，最重最全）
amass enum -passive -d example.com
```

::: tip 三个工具的区别
| 工具 | 本质 | 特点 |
|------|------|------|
| crt.sh | 查单一数据库（CT 日志） | 零安装、最快、只覆盖签过证书的 |
| subfinder | 聚合几十个被动源 | 覆盖广、快，日常标准做法 |
| amass | 重型资产发现平台 | 最全、最慢，还支持主动枚举 |
:::

> 拿到 `subs.txt` 就是一份「尽可能全」的域名清单，但里面混着大量「僵尸域名」，后面两步就是过滤。

---

## 三、第二步：DNS 解析（过滤解析不出的）

证书日志里很多域名**已经解析不出 IP**（域名过期、记录删了）。先做 DNS 解析，把这类直接排除。

```bash
# 单个域名解析
dig +short example.com

# 批量解析（dnsx 工具，速度快）
cat subs.txt | dnsx -silent -a -resp -o resolved.txt

# 或手工循环
while read d; do
  ip=$(dig +short "$d" 2>/dev/null | head -1)
  if [ -n "$ip" ]; then
    echo "$ip  $d"
  fi
done < subs.txt
```

::: tip 顺带收获
DNS 解析这一步还能**顺带判断目标是否套了 CDN**——如果解析出多个不同网段的 IP，大概率套了 CDN，后面要找真实源站 IP。
:::

---

## 四、第三步：存活检测（筛掉僵尸域名）

这是核心一步：**证书日志查出来的是「历史上存在过」的域名，不等于「现在还活着」。**

证书日志里有一堆「僵尸域名」：

- 域名注册了、签过证书，但**服务早下线了**
- 证书还在有效期内，但**后端已经关了**
- 只是做过 HTTPS 配置测试，**从来没真正上线**

所以必须做存活检测，筛出真正活着的。

### 两个层次：IP 存活 vs 域名存活

**层次 1：主机存活（IP 层，ping 扫描）**

```bash
# nmap ping 扫描
nmap -sn 192.168.1.0/24

# 很多服务器禁 ping，加 -Pn 更稳
nmap -sn -Pn 目标IP
```

**层次 2：域名/Web 存活（HTTP 层）**

```bash
# 单个域名，看状态码
curl -sI --max-time 10 https://example.com | head -1
```

### 批量检测（这才是实战场景）

```bash
# httpx（推荐，专为这个设计）
cat subs.txt | httpx -silent -status-code -title -o alive.txt

# 只看有价值的
cat subs.txt | httpx -silent -mc 200,301,302,403 -o alive.txt

# 或 curl 循环（不装工具也能做）
while read d; do
  code=$(curl -s -o /dev/null -w "%{http_code}" --max-time 8 "https://$d" 2>/dev/null)
  if [ "$code" != "000" ]; then
    echo "$code  $d"
  fi
done < subs.txt
```

### 判断「存活」的标准

| 返回 | 含义 | 要不要留 |
|------|------|----------|
| `200` | 正常访问 | ✅ 重点目标 |
| `301/302` | 重定向 | ✅ 跟进看跳哪 |
| `403` | 有服务但拒绝访问 | ✅ 可能藏东西 |
| `401` | 需要认证 | ✅ 登录框，弱口令目标 |
| `404` | 页面不存在（但服务器在） | ⚠️ 服务活着，目录可扫 |
| `000` / 超时 | 连接失败 | ❌ 跳过 |

::: danger 关键认知
`404` 不代表「死」——服务器是活的，只是那个路径没内容。所以 httpx 里 `-mc` 通常不排除 404，而是单独看「能不能建立连接」。
:::

## 五、第四步：指纹识别（锁定技术栈）

活的目标筛出来了，最后识别它背后是什么技术栈，为漏洞挖掘做准备。

```bash
# whatweb 识别 Web 指纹
whatweb http://目标IP:端口

# nmap 服务版本探测
nmap -sV -sC -p- 目标IP
```

**重点看四样东西：**

1. **Web 服务器**（Nginx / Apache / IIS / Tomcat）及版本 → 版本越旧，越可能有已知 CVE
2. **开发框架**（ThinkPHP / Spring / Flask / Django）→ 框架版本直接决定找什么 CVE
3. **CMS**（WordPress / Dedecms / 帝国）→ 对应找已知漏洞
4. **后端语言**（从 Cookie 判断）

| Cookie 特征 | 后端语言 |
|-------------|----------|
| `PHPSESSID` | PHP |
| `JSESSIONID` | Java / Tomcat |
| `ASP.NET_SessionId` | .NET |

## 六、完整链路总结

```
① 证书透明日志（crt.sh / subfinder / amass）
   解决「怕漏」→ 拿到尽可能全的域名清单
        ↓
② DNS 解析（dig / dnsx）
   解决「怕假解析」→ 过滤解析不出的域名
        ↓
③ 存活检测（httpx / curl）
   解决「怕假存活」→ 筛掉僵尸域名，留下活口
        ↓
④ 指纹识别（whatweb / nmap -sV）
   解决「怎么打」→ 锁定技术栈，进入漏洞挖掘
```

::: tip 核心认知
**证书查询是「广撒网」，存活检测是「过滤」，两者缺一不可。**
只查证书不检测 → 踩一堆死目标；只检测不查证书 → 漏掉很多域名。
:::

---

## 七、实战示例（完整跑一遍）

```bash
# ① 查证书，拿到域名清单
subfinder -d example.com -o subs.txt

# ② DNS 解析过滤
cat subs.txt | dnsx -silent -a -resp -o resolved.txt

# ③ 存活检测
cat resolved.txt | httpx -silent -status-code -title -o alive.txt

# ④ 指纹识别（对活的目标）
while read url; do
  whatweb "$url"
done < alive.txt
```

四步走完，你就得到了一份「又全、又活、又知道技术栈」的精准目标清单，可以直接进入漏洞挖掘阶段。
